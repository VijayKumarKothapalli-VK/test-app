# CI/CD pipeline for test-app

Generated by mule-cicd-kit 1.0.0 for **GitHub Actions**, deploying to **CloudHub 2.0**.

**Flow:** build + test -> publish to Exchange -> sandbox

Pull requests and other branches only run **build + test**. Pushes to `main` run the full flow.

## One-time setup

### 1. Create a Connected App in Anypoint
Access Management > Connected Apps > Create app > **App acts on its own behalf (client credentials)**.
Give it **Exchange Contributor** for the business group, and Runtime Manager permission to read, create,
delete and download applications in each environment you deploy to. Check MuleSoft's CloudHub 2.0
deployment docs for the exact scope list for your account.

### 2. Add these secrets to GitHub Actions
Repository > Settings > Secrets and variables > Actions > New repository secret. Add each one below.

- `ANYPOINT_CLIENT_ID`
- `ANYPOINT_CLIENT_SECRET`



### 3. Approvals
No environment needs approval.

### 4. Commit and push
Commit `.github\workflows\mule-cicd.yml`, the `cicd/` folder and the updated `pom.xml`, then push to `main`.

## Changing settings
Don't edit the generated files by hand. Change `cicd/pipeline-config.json` (or run the script again and answer
the questions), then run:

```
python create_pipeline.py <path-to-this-project> --use-saved
```

## Running a step on your own machine
Set `ANYPOINT_CLIENT_ID` and `ANYPOINT_CLIENT_SECRET` (and `MULE_KEY_<ENV>` for deploys) in your terminal, then:

```
bash cicd/mule-cicd.sh build
```

## Versions
The pipeline adds the build number to the pom version (e.g. 1.0.0 becomes 1.0.0-57), so you never need to bump it for a new build. Bump the pom version for a new feature release.
